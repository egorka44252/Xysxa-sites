# КРОК! — игра в крокодила

Игра для 2–5 друзей в одной комнате. Один выбирает слово из трёх вариантов или пишет своё и рисует на общем холсте. Остальные пишут догадки в чате. Сервер проверяет ответ, начисляет очки и запускает следующий раунд. Ход рисования переходит по кругу.

## Играть

Открой опубликованный сайт, введи имя и создай комнату. Отправь друзьям ссылку или шестизначный код. Создатель начинает игру, когда вошли хотя бы два игрока. У рисующего 80 секунд; первый правильный ответ сразу завершает раунд и приносит очки угадавшему и рисующему. Через 8 секунд ход автоматически переходит к следующему игроку.

У рисующего есть кисть с выбором размера, палитра и произвольный цвет, заливка области, очистка холста и отмена предыдущего мазка или заливки (`Ctrl+Z`, на Mac — `⌘Z`). Рисунок синхронизируется с остальными игроками во время рисования. Переключатель в шапке меняет светлую и тёмную темы; выбор запоминается в браузере.

Приватные токены игроков сохраняются только в браузере для возвращения в комнату. Комнаты и очки лежат в Cloudflare D1. Старые неактивные участники выходят из комнаты спустя три минуты; доступ к старым комнатам прекращается через семь дней без обновления.

## Запустить локально

Нужны Node.js 24+, pnpm 11 и Cloudflare Wrangler. Выполни `pnpm install`, `pnpm build`, затем применяй миграции к локальной D1:

```sh
pnpm exec wrangler d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_gifted_tag.sql
pnpm dev
```

Локальная D1 привязана в `vite.config.ts`. При дальнейших изменениях схемы запускай `pnpm db:generate` и применяй новые миграции отдельно.

## Разместить исходники на GitHub и запускать игру через Cloudflare

GitHub Pages обслуживает статические файлы, а этой игре нужен сервер для общей комнаты, чата и проверки ответов. Положи исходники в репозиторий GitHub; включённый workflow `.github/workflows/deploy.yml` публикует приложение в Cloudflare Workers при каждом push в `main`.

1. В своём аккаунте Cloudflare создай базу D1, например `krok-game`, и скопируй её UUID.
2. Создай Cloudflare API token с правами на Workers и D1. Добавь в GitHub Repository → Settings → Secrets and variables → Actions секреты `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `D1_DATABASE_ID`.
3. Загрузи файлы в ветку `main`. Workflow установит зависимости, соберёт Worker, применит миграции D1 и опубликует его. Адрес Workers появится в логе последнего шага.

Если база называется иначе, установи `D1_DATABASE_NAME` в шаге подготовки. Если нужен другой адрес Worker, установи `WORKER_NAME`. Не добавляй секреты в репозиторий.

При публикации через Sites файл `.openai/hosting.json` используется платформой для управляемой D1, а GitHub workflow создаёт отдельное развёртывание в твоём аккаунте Cloudflare. Это две независимые игровые базы.
